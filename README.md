# pitching-atlas

**成績や能力によらない、投手の地図を作る。** 球種のラベルも球速も使わず、
各投手の持ち球の**配分**だけで投手を3次元の座標に置く。データは2026年 MLB の
全投球（Statcast、レギュラーシーズン、400球以上の510投手）。

## 何をしたか

一球を、**縦変化・横変化・球速**の3次元ベクトルとして扱う。左投手は左右を反転し、
横変化はグラブ側を正とする。

**1. 谷は腕側とグラブ側の間にしかない。** 投手ごとにラベルなしで持ち球のピークを
検出し（3次元 mean shift、05）、ピークを結ぶ線上の谷の深さを測った（1.0 が谷なし、06）。

```
シンカー ⇔ スライダー   0.17     腕側とグラブ側の間：深い谷
スライダー ⇔ カーブ     1.00     グラブ側の中：連続（ST・SV・FC も同じ）
シンカー ⇔ チェンジ     1.00     腕側の中：連続
チェンジ ⇔ スプリット   1.00     区別できない
```

**2. どの投手の球も一枚の平面に乗る（Pitch Plane, PP）。**

```
球速[mph] ≒ 0.473 × 縦変化[in] − 0.156 × 横変化[in] + C
```

向き（係数）は年（2024: 0.477 / 0.144、2025: 0.475 / 0.150）でも利き腕でもほぼ変わらず、
投手ごとに違うのは高さ C だけ。平面の厚みは約1.3インチ。C は腕の振りの強さで、
速球の球速と順位相関 0.74。例外はチェンジアップとスプリットで、平面の予測より
約3 mph 遅い。

**3. だから球速は捨てられる。** 球速のうち変化量で説明できないのは、C と CH/FS の
わずかなずれだけ。C は球質の主成分（物理量だけで作った代用Stuff と順位相関 0.47）
なので、意図して外す。CH/FS のずれは、落下量に換算して地図に戻しても地図が
ほとんど変わらない（軸の相関 0.96 以上、近い10人の7割は同じ）ので無視する。

**4. 地図の3軸。** 原点は各投手のフォーシーム（投げない49人はシンカーかカッターから
リーグ平均の差で換算）。フォーシーム以外の球を、ピーク単位で腕側とグラブ側に分ける。

```
腕側／グラブ側          ln(腕側の球数 / グラブ側の球数) / √2
グラブ側：落とす／曲げる  ln(グラブ側の縦変化の合計 / 横変化の合計) / √2
腕側：落とす／流す       ln(腕側の縦変化の合計 / 横変化の合計) / √2
```

縦は上下どちらも量として数える。ほとんど投げない側でも比が暴れないよう、比を取る前に
小さな擬似量（球数比は割合 0.02、変化量比は 0.25 in／球）を足す。どの軸も
前半・後半の折半で再現性 0.99 以上。

## 確かめたこと

- **球質とほぼ無関係。** 3軸と代用Stuff の順位相関は最大 0.16（C は 0.47）。3軸を合わせても
  代用Stuff は予測できない（交差検証 R² −0.14〜−0.17。C だけなら +0.15）。xwOBA も
  予測できないが、1シーズンの xwOBA は C からも予測できないので参考程度。
- **タイプの違う投手を分ける。** Misiorowski・Sánchez・Sale・山本の4人は、再標本化の
  ばらつきを入れても互いに重ならない。山本の近くには Kelly・Stanek・Rodón、Sánchez の
  近くには Morejon・Houser・Matz（右腕も左腕も）が来る。
- **変化量をそのまま使っても、PP に投影しても同じ**（軸の相関 0.99 以上）。
- **年をまたいでも安定。** 2025年と2026年の位置の相関は 0.80〜0.87。

## 限界

- フォーシームを投げない投手の原点は換算なので、腕側の値の一部がリーグ平均で決まる。
  アンダースロー（Tim Hill、Tyler Rogers）では特に怪しい。
- 代用Stuff は本物の Stuff+ ではない（物理量だけで1球の得点価値を予測した簡易版）。
- 投手の位置は対戦打者の左右で変わる（3D地図では切り替えて見られる）。

経緯：探索の過程（球面への投影、多変量スペクトル分解、二つの扇など）は
[pitch-vectors](https://github.com/seal-husband/pitch-vectors) にある。このリポジトリは、
そこから記事に必要な部分だけを取り出して番号を振り直したもの。結果は同じ。
その前身の `baseball-atlas` は球種を「横・縦・遅さ」の三つの箱に束ねて軸にしていた。

## 構成

```
pitching-atlas/
├── run_all.py          全スクリプトを番号順に実行
├── src/                解析スクリプトと共通モジュール（paths.py, common.py, fourparts.py）
├── data/               Statcast の一球データ（各自で取得、リポジトリには含めない）
├── output/             中間結果と表（*.parquet, *.npz, *.csv。再生成できるので含めない）
│   └── figures/        図（ファイル名の先頭はそれを描くスクリプトの番号）
│       └── note/       note 記事用の4枚（15 が描く）
└── web/                ページ（three.html：投手の地図、cloud.html：全投球の雲）。データ *_data.js は 08・16 が書き出す（含めない）
```

```
src/00_fetch_statcast.py   1シーズン分の Statcast を1日ずつ取得・追記（python src/00_fetch_statcast.py 2026）
src/01_pitch_plane.py      PP の特定：向き・厚み・年や利き腕による違い → output/plane_2026.npz
src/02_plane_height.py     投手ごとの PP の高さ C → output/plane_height_2026.csv
src/03_stuff_standin.py    代用Stuff（物理量だけで1球の得点価値を予測）と、PP からのずれ・C と成績
src/04_pitch_table.py      全投球を PP 上の座標に → output/pitches_pp_2026.parquet
src/05_peaks.py            投手ごとのラベルなしピーク検出（3次元 mean shift＋持続性による合併）
src/06_valleys.py          ピークを結ぶ線上の谷：腕側とグラブ側の間だけに谷がある
src/07_four_numbers.py     フォーシーム基準（投げない投手は換算）と4つの数（腕側・グラブ側 × 横・縦、側の割合）
src/08_map.py              地図の3軸（対数比）→ web/three_data.js
src/09_separation.py       4人の位置のぶれ（再標本化）と組ごとの隔たり、近い投手
src/10_reliability.py      折半の再現性と、擬似量 δ・ε への感度
src/11_map_vs_stuff.py     地図の3軸と代用Stuff・xwOBA の無関係、C・速球の球速との比較（図 11_c_vs_stuff.png）
src/12_stability.py        アームアングル・打者の左右・年をまたいだ安定性
src/13_projection_vs_raw.py 変化量をそのまま使う地図と PP に投影した地図の比較
src/14_offplane_check.py   CH/FS の遅さを落下に換算して地図に戻しても、地図はほぼ変わらない
src/15_note_figures.py     note 記事の図4枚 → output/figures/note/
src/16_cloud_data.py       図1の雲を回して見るページのデータ → web/cloud_data.js（web/cloud.html）
src/common.py              共通の定数（対象の球種、400球以上、0.63 in/mph）
src/fourparts.py           4つの数の計算（側はピーク単位、縦は上下どちらも）
```

## 動かし方

```
pip install -r requirements.txt
python src/00_fetch_statcast.py 2024     # Statcast を1日ずつ取得（時間がかかる）
python src/00_fetch_statcast.py 2025
python src/00_fetch_statcast.py 2026
python run_all.py                        # 全スクリプト（約7分）。python run_all.py 08 15 のように一部だけも可
```

一球単位のデータは `data/statcast_YYYY.parquet`（1シーズン1ファイル）に置かれる。別の場所に置く場合は
環境変数 `PITCHING_ATLAS_DATA` で指定する。2024・2025年は、PP の年ごとの安定性（01）と、
地図の年をまたいだ安定性（12）の確認にだけ使う。

結果は 2026年3月18日〜9月27日（レギュラーシーズン全日程）、743,373球のデータで出している。
00 はすでにあるファイルの最終日から追記するので、途中で止めても続きから取れる。

ページ（`web/three.html`、`web/cloud.html`）は、08・16 がデータ（`web/*_data.js`）を書き出したあとで開く。
ブラウザがローカルの JavaScript を読めるよう、`web/` で簡易サーバーを立てる。

```
cd web
python -m http.server 8000               # http://localhost:8000/three.html、cloud.html
```

## データとライセンス

Statcast のデータの権利は MLB Advanced Media にあり、個人的・非商用の利用に限られる。
このリポジトリには、一球単位のデータも、そこから作った中間結果・表・ページ用データも含めない。
すべて上の手順で各自が再生成する。図（`output/figures/`）は含める。
